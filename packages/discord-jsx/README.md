# @ariesclark/discord-jsx

Build Discord [Components V2](https://docs.discord.com/developers/components/reference) message
payloads with JSX. Elements evaluate directly to plain `discord-api-types` objects: no React, no
reconciler, no build step.

Component tags, their props, and their types are **derived from `discord-api-types`**: every
`ComponentType` enum member becomes a tag, and its props are the API payload's own fields
(already snake_case) with `children` standing in for `components`/`items`/`content`. When the
package adds a new component type, a new element appears here automatically.

Markdown inside text comes from [`@ariesclark/markdown-jsx`](../markdown-jsx), whose elements
are merged into the same runtime.

```tsx
const content = (
  <message>
    <container accent_color={0x7289da}>
      <section accessory={<thumbnail media={{ url: avatarUrl }} />}>
        <text>
          <h3>
            <a href={compareUrl}>3 new commits</a>
          </h3>
        </text>
        <text>
          <small>pushed by {sender}</small>
        </text>
      </section>
    </container>
  </message>
);
// { flags: 32768, components: [{ type: 17, accent_color: 7506394, components: [...] }], files: undefined }
```

## Consuming as intrinsics

```jsonc
// tsconfig.json
{
  "compilerOptions": {
    "jsx": "react-jsx",
    "jsxImportSource": "@ariesclark/discord-jsx"
  }
}
```

Tags are the lowercased enum names: `container`, `section`, `thumbnail`, `separator`,
`button`, `actionrow`, `file`, plus two readability overrides (`TextDisplay` → `text`,
`MediaGallery` → `gallery`), the markdown elements (`b`, `i`, `code`, `a`, `h1`–`h3`,
`small`, `br`, …), and `message`.

`<message>` wraps top-level components into a `WebhookContent`: the
`RESTPostAPIWebhookWithTokenJSONBody` payload with `IsComponentsV2` set, extended with an
optional `files` prop for `attachment://` uploads:

```tsx
<message files={[{ name: "authors.png", data: pngBytes }]}>
  <section accessory={<thumbnail media={{ url: "attachment://authors.png" }} />}>
    <text>…</text>
  </section>
</message>
```

## Consuming as imports

Every component is also exported by its enum name, a plain function from props to an API object,
generated by a typed `Proxy`, usable under any JSX runtime or with no JSX at all:

```ts
import { Container, Message, Section, TextDisplay, Thumbnail } from "@ariesclark/discord-jsx";

Message({
  children: Container({
    accent_color: 0x7289da,
    children: Section({
      accessory: Thumbnail({ media: { url } }),
      children: TextDisplay({ children: "hello" }),
    }),
  }),
});
```

The full set is available on the `components` proxy (`components.StringSelect`, …); common ones
are re-exported directly: `ActionRow`, `Button`, `Container`, `File`, `MediaGallery`,
`Message`, `Section`, `Separator`, `TextDisplay`, `Thumbnail`.

## Custom components

Capitalized functions compose as usual, taking props and returning whatever they render:

```tsx
function RepositoryName({ repository }: { repository: { full_name: string; html_url: string } }) {
  return (
    <b>
      <a href={repository.html_url}>{repository.full_name}</a>
    </b>
  );
}

<text>
  <RepositoryName repository={repository} /> pushed to <code>{branch}</code>
</text>;
```

Async components work too (`async function Variant(props): Promise<WebhookContent>`);
rendering one returns a promise to `await`.

## Caveats

- `JSX.Element` is `any`: element *placement*, a text where a container child belongs, is not
  type-checked, only props are. Validate output against Discord, ideally with snapshot tests.
- JSX whitespace rules apply: explicit `{" "}` between elements across line breaks, `<br />`
  for newlines.
- Sending a `WebhookContent` with `files` requires a multipart request (`payload_json` +
  `files[n]` parts); without files it is plain JSON. The `files` field itself must not be
  serialized into the payload.
